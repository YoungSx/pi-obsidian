## Anti-Patterns Verdict

**LLM 判断：不像 AI 生成的。** 这是 product register，familiarity 本身是优点，检验标准是「用 Linear/Raycast/Cursor 的人坐下来会不会信它」——会。没有渐变字、没有毛玻璃、没有 eyebrow 小字、没有等大卡片阵、没有侧边色条、没有 hero 数字模板。它长得像 Obsidian 原生，因为它真的只用 Obsidian 的语义 token，一个硬编码颜色都没有。

一处 interaction slop（不是视觉的）：模型生成的「一键追问」小药丸，现在 ChatGPT / Gemini / Copilot 全都在发这个货。空屏那排是刚需，回复后那排是纯装饰。

**确定性扫描：跑了，干净，但这份干净是弱证据。** `detect.mjs --json src/ui` 退出码 0，返回 `[]`。原因要说清楚：它是 HTML/CSS 规则引擎，面对 TSX + 全 Obsidian 变量的样式表，对比度规则解析不出具体颜色，slop 规则也匹配不到 JSX。它的沉默不等于背书。

**视觉叠加层：没有。** 无浏览器自动化工具，且 Obsidian 插件没有 dev server / localhost URL 可注入（`paseo.json` 只有一条 `bun i`）。没有起本地服务，没有注入脚本，所以浏览器里不存在任何叠加层。这一轮的证据全部来自源码通读。

## Overall Impression

这面板的工艺水平，说实话超过大多数商业产品。无障碍那一块尤其狠：live region 谁播报谁不播报分得干干净净，`--icon-color` 而不是 `opacity` 那段还附了 2026-08-28 在 Chromium 实测的对比度数字。代码注释读起来像人写的设计备忘录，不像 AI 吐的。

问题不在手艺，在**权力**。用户能做的事太少了。你说出去的话，收不回来、改不了、重发不了；模型动了你的笔记，撤不回来；上下文快满了，只有角落一个 16px 圆环偷偷变橙。面板把「说清楚」做到了满分，把「让我改」漏掉了。

最大的机会一句话：**给用户一把方向盘。**

## What's Working

**1. 无障碍不是补丁，是骨架。**
不是"加了 aria-label"那种。是想到了：live region 必须在内容变化之前就已经在 DOM 里，所以 `ChatStatusBar` 空闲时收成 `visually-hidden` 而绝不 unmount；流式消息不能当 live region，否则读屏会把半个词循环念一遍，所以另开 `TurnAnnouncer` 只播报落定的那一轮；错误走 `assertive`、通知走 `polite`，因为"没什么可压缩的"不该打断人。再加 WCAG 2.4.1 的跳过链接、`aria-keyshortcuts`、combobox + `aria-activedescendant` 全套、以及关掉 chip 之后把焦点交给顶替它的那个控件。这是教科书。

**2. 触摸不是事后想起来的。**
`isDesktopOnly: false` 被当真了。全文件没有一个 hover-only 控件；hover 规则一律包在 `@media (hover: hover)` 里，因为手机上点一下 `:hover` 会赖着不走；`any-pointer: coarse`（尺寸）和 `pointer: coarse`（布局）分得很清——iPad 插键盘报 `fine`，但拇指还是主要输入。React 层还按 `Platform.isMobile` 把历史按钮从 header 撤走，好让那一行只占一层楼高。

**3. 渐进披露真的在披露。**
所有机器流量——工具调用、工具结果、思考、harness 输出——统一收成一行可展开的 trace。数字从占满一行的横条挪进圆环的 popover。`showAgentDetails` 这一档把"压缩上下文"和"整理旧消息"分成两套措辞。认知负荷清单 8 项只差半项，属于 low。

## Priority Issues

### [P1] 自己发出去的话，是一块石头

用户消息上零操作。不能编辑、不能重发、不能复制（只能手动划选）。`ReplyActions` 只挂在 assistant 上。

**为什么要命**：打错一个字、漏了一句条件、想换个问法——唯一的路是整条重打。而"改一下再问"是所有成熟聊天 UI 的**首要**纠错通道（ChatGPT、Claude、Cursor 全是）。`retryFrom` 能重跑，但不能改；它退回到那个问题，却不让你碰那个问题。启发式 #3 和 #9 双杀，也是 29 分里扣得最狠的一处。

**怎么修**：用户消息加一个「编辑并重发」——点进去把原文放回 composer，从该轮截断后重发。语义上和 `retryFrom` 是同一个 rewind，只是中间插了一次编辑。可以复用 `regenerableIndex` 那套"只允许最新一轮"的约束，先只给最后一条用户消息开这个口子。

**建议命令**：`/impeccable harden`

### [P1] 长跑的时候，没人告诉你它还活着

一次 3 分钟、12 个工具调用的 agentic run，屏幕上有什么？一个转圈 + 「Working: 读取笔记」。没有耗时、没有步数、没有"第 12 步"。`ChatStatusBar` 这个组件的可见占空比大约 2%——它只会说"正在打开聊天"和"正在整理旧消息"，其余时间收成隐藏。

**为什么要命**：这是所有 agent UI 的头号焦虑，用户的原话永远是"它是不是卡死了"。这里没有任何东西回答这个问题。停止按钮在，但要不要按取决于"它还在动吗"，而这一点无从判断。启发式 #1。

**怎么修**：给在飞的这一轮加耗时（`0:47`）和步数（`第 12 步`）。位置有现成的：pendingToolCalls 那行右侧，或者复活 `ChatStatusBar` 那 98% 的闲置。不需要新组件。

**建议命令**：`/impeccable harden`

### [P1] 上下文墙是撞上才知道的

圆环的注释自己承认了："16px 下没人分得清 60% 和 75%"，所以精度搬进了 popover。合理。但**阈值时刻**恰恰是不该等人来问的时刻。现在从 ok → warn → near 的全部信号，就是发送栏角落一个 16px 圆圈换颜色。不 hover，什么都不说。

更糟的是 `meterTitle` 里那句"包括什么都不会发生的情况，因为自动整理是关的"——自动压缩可以是关的。那用户就是直接撞墙。而压缩分隔线是**事后**才出现的。

**为什么要命**：这是每个读者都会撞的墙，不是只有盯 token 的人才撞。而且它可以让人当场丢掉一轮。启发式 #1 + #5。

**怎么修**：进 `near` 的时候升级通道——`ChatBanner` 出一条 notice（现成的 polite 通道），文案直说"快满了，整理一下？"外加一个跑 `onTidy` 的按钮。读屏用户目前对这件事**完全**收不到通知，因为值只活在按钮的 accessible name 里，没有人去读它。

**建议命令**：`/impeccable harden`

### [P2] 第一次用的人，读到的是全场最小最淡的字

`.piem-chat__empty` 是 12px（`--font-ui-smaller`）+ `--text-muted`。标题 13px。也就是说，整个产品的**首次说明**——"Piem 可以在这里读取、搜索和编辑笔记"——用的是面板里最小的字号和次一级的颜色。

而这个文件自己的头部注释写着：`meta` 档（12px）是"扫的，不是读的"。这段恰恰是唯一必须被读的。

**为什么要命**：Jordan（第一次用的人）唯一的指引在这里，而它被排版成了脚注。叠加 #10 那个 1 分——面板里没有任何帮助入口，那这段小字就是全部的帮助。

**怎么修**：空屏正文提到 `--font-ui-small`（13px，`ui` 档，"是句子的 chrome"），标题提到 `--font-ui-medium`（15px，`read` 档）。这是空屏，没有密度压力，那点高度出得起。

**建议命令**：`/impeccable typeset`

### [P2] 跳过链接只有单向

跳过链接（WCAG 2.4.1）修的是**向前**：一次 Tab 从顶部跳到 composer。但反向没修——从 composer 按 Shift+Tab 往回走，还是要穿过全部按钮。每条回复 3–4 个按钮，20 轮就是 60–80 个，外加每个 trace 的 summary。

**为什么要命**：读屏和纯键盘用户在 composer 里待的时间最多，而"回到刚才那条回复"是他们最常做的动作。合规过了，实际路径没过。

**怎么修**：两条路。一是给 transcript 加"跳回对话"的反向链接（transcript 本身已经 `tabIndex={0}` 可聚焦，指它就行）。二是治根：把每条回复的操作收进一个「⋯」，把 4 个 tab stop 压成 1 个——他们为了触摸可达而否决了 hover-only，这是对的，但溢出菜单同时满足触摸和低密度。

**建议命令**：`/impeccable polish`

## Persona Red Flags

**Alex（急性子老手）**：
- 自己的消息改不了。他打错一个 flag，得整段重打——这是他第一个会骂的点。
- 会话内无搜索。40 轮的对话里找"刚才那个路径"，只能滚。
- 无法按轮次跳键盘。`role="log"` 可聚焦，但里面的消息不是独立 tab stop，跳转靠读屏的浏览模式。
- 亮点：8 条命令面板入口全可绑热键、`/` 模糊匹配、会话选择器 Shift+↵ 直接删。这一块他会满意。

**Sam（无障碍依赖者）**：
- **上下文快满，完全收不到通知。** 值只在按钮的 accessible name 里，跨过 near 阈值时没有任何播报。这是他唯一会真受伤的地方。
- 反向 Tab 要穿 80 个按钮（见上）。
- `aria-busy` 在 `.piem-chat`、transcript、pending article 上三层嵌套。大概无害，但是冗余。
- 其余：这是他这个月体验最好的界面。live region 纪律、跳过链接、combobox 全套、关闭后的焦点交接、以及实测过的对比度——都对。

**Casey（走路上单手用手机的人）**：
- 280px 宽时发送栏 4 个控件：模型名（省略号吃到只剩"clau…"）、大脑图标、圆环、Send + 键帽。模型名这个唯一存在理由就是"报出模型"的东西，读不出来了，但还占着位。
- 每条回复后面跟一排 48px 高的 4 个按钮（coarse pointer 下 `--size-4-12`）。手机上每轮回复都要付一整行楼层。
- 长跑没有耗时——她最需要的就是这个，因为她盯着的就是这块屏。
- iOS 点击抢焦点：他们知道，`keepFocusOnPress` 的注释写着这是"安慰，不是保证"。诚实，但问题还在。
- 亮点：header 在手机上被压回一行，这是对的取舍。

## Minor Observations

- **zhCN 覆盖约 65%**（714 行 vs en 1100 行）。`DeepPartial<EnCopy>` + 英文回退这个机制设计得很干净，但结果是中文用户会看到混语界面。机制没问题，缺的是翻译量。
- **Escape 不统一**。ContextGauge popover 和 CommandMenu 都处理，composer 和 transcript 不处理。
- **重新生成没有二次确认**，他们的解法是把它限死在最新一轮（注释写了理由，成立）。但如果那一轮跑过写笔记的工具，重跑不会撤销已经落地的那次写入 —— 就变成半个已应用的修改 + 再跑一遍。**这一条我只读了 UI 层，没读 `retryFrom` 的服务端实现，属于未核实的风险，不是已确认的缺陷。**
- **会话已经在 vault 里**（`DEFAULT_SESSION_DIR = "Piem/chats"`），但是 `.jsonl`。所以"导出整段对话成笔记"这个动作缺失，但缺得比看起来轻——文件已经在那儿了，只是不是人读的格式。对一个以笔记为前提的插件来说，「把这段聊天存成笔记」还是个显眼的空位。
- **`/` 命令的发现性挂在一根线上**：placeholder"询问 Piem，或输入 / 使用命令…"。打第一个字，这条广告永久消失。⋯ 菜单里没有命令列表，没有 `/` 按钮。用户永远发现不了 skills。

## Questions to Consider

- 如果"编辑并重发"是这个面板的**主要**纠错动作，而不是补丁，composer 会长什么样？
- 圆环赌的是"一眼看颜色就够了"。如果这个赌注错了呢？——一个必须先 hover 才能读的仪表，在最需要它的那一刻恰恰是不可读的。
- 每条回复挂 4 个永久按钮，是真的每条都需要，还是只有最新那条需要？
- 面板里一个帮助入口都没有。如果 `/` 命令本身就是帮助的入口呢——`/help` 会不会比一个问号图标更贴这个产品？
- 一次 3 分钟的 agentic run，如果**必须**只显示一个数字，那个数字是耗时，还是步数？
